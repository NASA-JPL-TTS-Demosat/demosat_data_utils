# Ticket 15 Implementation Reasoning

## Overview
Implemented EHA alarm row styling for `DemosatChannelFrame` via the row-series mechanism. Styling reads `dnAlarmState` and `euAlarmState` case-insensitively, gives red precedence over yellow, ignores `status`, and returns a stable neutral style for unalarmed rows.

## Decisions

### Row-series styling
- Implemented `DemosatChannelRowSeries.default_html_row_style` as the styling hook. This is the mechanism used by `TtsDataFrame` rendering and `PowerTable` row coloring.
- `DemosatChannelFrame.ROW_SERIES_CLASS = DemosatChannelRowSeries` ensures every row view is wrapped as `DemosatChannelRowSeries`.

### Alarm source selection
- Explicitly read only `dnAlarmState` and `euAlarmState` via `self.get`. `status` is never inspected, satisfying the requirement that alarm styling is not driven by channel status.
- Mirrors AMPCS EHA semantics but adapts to Demosat column names.

### Case-insensitive handling
- Normalization helper strips whitespace and lowercases the state value. Non-string values, including `None`, `np.nan`, and pandas `NA`, fall back to empty string.
- This makes `"RED"`, `"red"`, `" Red "` equivalent and avoids errors on missing data.

### Precedence and mapping
- Red check performed before yellow check, guaranteeing red-over-yellow precedence regardless of which column provides the alarm.
- Color mapping matches AMPCS conventions: red → `#FFCCCC`, yellow → `#FFF3CC`. Neutral rows return `{}` for stable, empty styling.

### Robustness
- `normalize` guards against non-string inputs, preventing `AttributeError` on `strip`.
- `self.get(col, "")` supplies a default if the column is absent, so schema-permissive frames do not raise.
- Empty/null/pandas-missing values normalize to `""` and fall through to neutral style.

## Trade-offs
- Returning `{}` for neutral keeps the implementation minimal and consistent with `TtsRowSeries.default_html_row_style` base implementation. An explicit background color could be added later if UI requires a default row color, but empty dict is the documented neutral signal.
- Normalization is performed per property access; cost is negligible for table rendering and keeps logic self-contained.
- No dependency on external configuration for alarm strings; hard-coded `"red"`/`"yellow"` matches Demosat telemetry spec and AMPCS conventions.

## Verification
- Existing tests `test_alarm_styling` and `test_status_not_used_for_alarm` validate:
  - No alarm → `{}`.
  - Yellow from either column → yellow style.
  - Red from either column → red style.
  - Red precedence over yellow when both present.
  - `status` values do not affect styling.
  - Uppercase and lowercase values both work.
- All 48 tests in `src/demosat_data_utils/test/` pass.
